# Agentic RAG のポテンシャルを見せる追加デモケース

この資料は、従来型RAGよりも Agentic RAG の強みが出やすいデモ材料です。
`04` 以降のPDFは `create-agentic-potential-pdfs.mjs` で生成します。

## 使い方

1. `docs/demo-files/*.pdf` をアプリにアップロードする。
2. まず単一PDFケースで MinerU の構造化効果を見せる。
3. 次に複数PDFケースで、Agent が検索を反復しながら情報を結合する様子を見せる。
4. 実行ログでは `rewrite_query`、`retrieve`、`vector_search`、`bm25_search`、`rerank`、`expand` を開く。
5. 回答内の引用をクリックし、右パネルで根拠を確認する。

## Case 1: ページ跨ぎ表の semantic loss を回避する

対象PDF:

- `04-cross-page-table-semantic-loss.pdf`

見せたいこと:

- 表がページをまたぎ、2ページ目が表本文から始まる。2ページ目には列ヘッダーが再掲されない。
- 従来RAGでは2ページ目だけがチャンク化されると、`0.91 / 0.88 / N9 / 翌営業日AM` が何の列なのか失われる。
- MinerU が表ブロックとページ位置を保持し、Agentic RAG が前ページの表ヘッダーや周辺チャンクを取りに行くことで列意味を復元できる。
- 「暫定判定」「注記コード」「部品到着予定」「本文の例外条件」を結合して初めて結論が出る。

質問例:

> MX-17は即時停止すべきですか？点検表の計測値、継続表の注記コード、本文の例外条件を分けて説明してください。

期待回答の要点:

- MX-17はヘッダーなしで始まる2ページ目の継続行にある。
- 前ページの表ヘッダーを復元すると、MX-17は `振動=0.91`、`温度=0.88`、`電流=0.74`、`暫定判定=停止候補`。
- 同じ行の注記コードは `N9`、部品到着予定は「翌営業日AM」。
- N9は即時停止推奨だが、部品が翌営業日AMに到着する場合は夜間停止枠まで運転継続可能。
- 最終結論は「即時停止推奨に該当。ただし夜間停止枠までの運転継続例外あり」。

従来RAGとの差:

- 1回の上位チャンクだけでは、2ページ目の数値とコードが列名なしで取得され、意味が欠ける。
- 通常のテキスト抽出では「ページ2の最初の行」がただの値列になり、表1のヘッダーと結びつかない。
- Agentic RAGなら、最初の検索で列意味が足りないことを検知し、前ページの表ヘッダー、周辺チャンク、補足本文を追加取得できる。

## Case 2: 画像・図面を根拠として参照する

対象PDF:

- `05-image-grounding-cooling-line.pdf`

見せたいこと:

- 画像そのものは通常のテキストembeddingだけでは意味検索しづらい。
- MinerU が図面領域を画像・キャプションとして切り出すことで、右パネルで一次資料として確認できる。
- 図面の赤枠、キャプション、本文の一次対応を結合して交換対象を特定する。

質問例:

> T2温度上昇とF1流量低下が同時に出た場合、図面上のどの部品を第一候補として交換・点検すべきですか？HX-7との違いも説明してください。

期待回答の要点:

- 赤枠は `V-12バイパス弁`。
- T2温度上昇とF1流量低下が同時に出た場合、V-12固着を第一候補として点検。
- HX-7は洗浄対象だが交換対象ではない。
- 根拠は図1キャプションと一次対応本文。

従来RAGとの差:

- テキスト化された本文だけでは「赤枠」が何を指すか追いづらい。
- Agentic RAGでは、回答だけでなく図面切り出しを引用パネルで確認できる。

## Case 3: 複数ファイルを結合して候補を決める

対象PDF:

- `06-multi-file-requirement-request.pdf`
- `07-multi-file-security-policy.pdf`
- `08-multi-file-vendor-quotes.pdf`

見せたいこと:

- 要求仕様、セキュリティ規程、見積一覧が別ファイルに分かれている。
- どれか1つのPDFだけでは採用候補を決められない。
- Agentic RAG が複数文書を横断し、条件を満たす候補を消去法で選ぶ。

質問例:

> エッジAIゲートウェイを1つ選ぶならどれですか？要求仕様、セキュリティ規程、見積を照合して、不採用候補の理由も含めて答えてください。

期待回答の要点:

- 採用候補は `AlphaGate X2`。
- 納期 `2026-06-05` は要求期限 `2026-06-07` 以内。
- 初年度費用 `92万円` は通常目安80万円を超えるが、緊急保守の許容上限95万円以内。
- 国内リージョン、365日ログ保管、ローカル推論、ISO 27001を満たす。
- BetaEdge Miniは納期が `2026-06-15` で期限超過。
- GammaVision Cloudは海外リージョン、90日ログ、ローカル推論なしで不適合。

従来RAGとの差:

- 上位チャンクが見積PDFに偏ると、価格だけでBetaEdgeを選びやすい。
- 規程PDFに偏ると、実際にどの候補が条件を満たすか判断できない。
- Agentic RAGなら「要求 → 規程 → 見積」の順に検索を追加し、結論を組み立てられる。

## Case 4: 曖昧な社内略語を rewrite query で展開する

対象PDF:

- `09-query-rewrite-acronym-runbook.pdf`

見せたいこと:

- ユーザーは正式名称ではなく「RED route」「P2 chatter」などの社内略語で質問する。
- Agent が略語集を見つけ、検索語を正式名称・運用語に展開してからRunbookを読む。
- `rewrite_query` の意義を説明しやすい。

質問例:

> RED routeでP2 chatterが出ている。まず何を確認して、暫定対応と恒久対応は何をすべき？

期待回答の要点:

- RED route = Revenue Event Delivery route。
- P2 chatter = P2アラートが短時間に発火・復旧を繰り返す状態。
- 最初にKafka consumer lagを確認。
- 暫定対応はdedupe windowを60秒から180秒へ変更。
- 10分以内に再発する場合はshadow ackを有効化し、顧客通知を一時停止。
- 恒久対応はidempotency keyを注文ID + 明細IDへ変更。

従来RAGとの差:

- 質問語と本文語彙がずれると、単発検索ではRunbookに届かない。
- Agentic RAGなら略語集を拾い、検索語を言い換えて再検索できる。

## Case 5: 最新ルールと一時例外を同時に判断する

対象PDF:

- `10-exception-latest-rule-conflict.pdf`

見せたいこと:

- 最新版の基本ルールと、期限付き例外メモが同じPDF内に存在する。
- 「いつ」「どの顧客」「どの部署」かで結論が変わる。
- Agent が条件分岐を読み、適用できる例外と省略できない条件を分ける。

質問例:

> 2026-05-25に、カスタマーサクセス部が低リスク顧客へAI回答を提示する場合、部長承認・担当者レビュー・根拠確認・保存期間はどうなりますか？

期待回答の要点:

- 2026-05-25は例外メモ EX-44 の期間内。
- カスタマーサクセス部の低リスク顧客向けFAQ回答なら、部長承認は省略可能。
- 担当者レビュー、根拠資料確認、180日保存は省略不可。

フォローアップ質問:

> では2026-06-20ならどう変わりますか？

期待回答の要点:

- 例外期限 `2026-06-10` を過ぎているため基本ルールに戻る。
- 高リスク顧客なら部長承認が必要。
- 担当者レビュー、根拠資料確認、180日保存は引き続き必須。

従来RAGとの差:

- 例外メモだけを拾うと「部長承認不要」と誤答する。
- 基本ルールだけを拾うと「常に部長承認必要」と誤答する。
- Agentic RAGなら日付条件と例外範囲を照合して回答を変えられる。

## Case 6: 否定条件を探して「できない理由」を答える

対象PDF:

- `06-multi-file-requirement-request.pdf`
- `07-multi-file-security-policy.pdf`
- `08-multi-file-vendor-quotes.pdf`

見せたいこと:

- RAGは「できる理由」より「できない理由」の検索が難しい。
- Agentic RAGでは候補ごとに条件をチェックし、不採用根拠を引用付きで説明できる。

質問例:

> GammaVision Cloudを採用できない理由を、要求仕様とセキュリティ規程の両方から説明してください。

期待回答の要点:

- 要求仕様はローカル推論モードを必須としているが、GammaVision Cloudはローカル推論なし。
- セキュリティ規程は海外リージョンのみのログ保管を不可としているが、GammaVision Cloudは海外リージョン。
- 監査ログ保存も90日で、規程の180日以上に満たない。

従来RAGとの差:

- 上位検索結果に価格の安さだけが出ると誤って採用可能と見える。
- Agentic RAGなら「不採用理由」を探す追加検索に進める。

## Case 7: フォローアップで回答形式を変える

対象PDF:

- `06-multi-file-requirement-request.pdf`
- `07-multi-file-security-policy.pdf`
- `08-multi-file-vendor-quotes.pdf`

質問例:

> エッジAIゲートウェイを1つ選ぶならどれですか？

フォローアップ:

> その判断を購買部が確認できるチェックリストにしてください。各項目に根拠文書も付けて。

見せたいこと:

- 2ターン目では「その判断」が前ターンの採用候補を指す。
- Agentic RAGが会話履歴を使い、同じ根拠をチェックリスト形式へ再構成できる。

従来RAGとの差:

- 毎回単発検索するだけだと、前ターンの結論やユーザーの意図を保持できない。
- Agentic RAGでは履歴を使い、必要なら同じ文書を再検索して形式変換できる。

## Case 8: 既存デモPDFと組み合わせる総合シナリオ

対象PDF:

- `01-mineru-layout-report.pdf`
- `04-cross-page-table-semantic-loss.pdf`
- `05-image-grounding-cooling-line.pdf`

質問例:

> ラインAのPoCで優先して説明すべきリスクを、既存レポートのRisk式、ページ跨ぎ点検表、冷却ライン図面の根拠を使って3点にまとめてください。

見せたいこと:

- 1つの質問で、数式、ページ跨ぎ表、図面キャプションという異なる構造を横断する。
- 従来RAGでは検索結果が散らばり、根拠の粒度が揃わない。
- Agentic RAGでは不足情報を取りに行き、異種ブロックを統合できる。
